## 1. المبادئ العامة

### تعريف العقار الجديد والقديم

| النوع | التعريف | السلوك |
|---|---|---|
| عقار جديد | لا يملك اشتراكاً سابقاً له تاريخ نهاية محفوظ | لا يتم تفعيل اشتراكه مباشرة، حتى لو دفع ونجح Smart Verify |
| عقار قديم | يملك اشتراكاً سابقاً أو حالياً | يستمر بالسلوك الحالي: التفعيل التلقائي بعد نجاح الدفع وSmart Verify |

### القاعدة الأساسية للعقار الجديد

- العقار الجديد المجاني ينتظر موافقة الأدمن.
- العقار الجديد المدفوع ينتظر موافقة الأدمن بعد نجاح الدفع وSmart Verify.
- الدفع الناجح للعقار الجديد يحفظ تواريخ الاشتراك المعلقة، لكن لا ينشئ اشتراكاً نشطاً قبل اعتماد الأدمن.
- بعد اعتماد الأدمن، يتم تفعيل الاشتراك من بيانات الدفع المعلقة.

## 2. حالات الدفع والتحقق

| الحالة | المعنى |
|---|---|
| `قيد المراجعة` | يحتاج مراجعة إدارية، أو الإيصال/Smart Verify لم يكتمل تلقائياً |
| `نجح - قيد التحقق` | الدفع ناجح والاشتراك ينتظر استكمال التحقق أو اعتماد الأدمن |
| `مكتمل` | الدفع مقبول والاشتراك مفعّل |
| `مرفوض` | رفض نهائي من الإدارة أو خطأ لا يمكن إكماله مثل باقة غير موجودة |
| `معلق` | بدأ الدفع ولم يكتمل بعد |

| حالة العقار | المعنى |
|---|---|
| `pending` | ينتظر اعتماد الأدمن أو استكمال بيانات |
| `approved` | معتمد ويظهر للعامة |
| `rejected` | مرفوض إدارياً |

## 3. الاشتراك الأول للعقار الجديد

### عقار جديد + باقة مجانية

```
المالك يسجل العقار
  → يكمّل البيانات
  → Run Verification يعمل تلقائياً عند الحفظ مرة واحدة
    ✅ البيانات مكتملة → يبقى verificationStatus: pending وينتظر الأدمن
    ❌ البيانات ناقصة → يبقى pending وتظهر الحقول المطلوبة
  → الأدمن يعتمد العقار
    → يظهر العقار للعامة
```

### عقار جديد + دفع إلكتروني

```
الدفع الإلكتروني ينجح
  → Smart Verify يعمل
    ✅ البيانات مكتملة
      → payment.status: "نجح - قيد التحقق"
      → حفظ pendingStartDate / pendingEndDate
      → verificationStatus: pending
      → انتظار اعتماد الأدمن
      → لا يتم إنشاء اشتراك نشط الآن
    ❌ البيانات ناقصة
      → payment.status: "نجح - قيد التحقق"
      → توضيح الحقول الناقصة للمالك
      → زر تعديل بيانات العقار
```

### عقار جديد + تحويل بنكي

```
المالك يرفع الإيصال
  → AI يفحص الإيصال
    ✅ الإيصال مقبول
      → Smart Verify
        ✅ البيانات مكتملة
          → payment.status: "نجح - قيد التحقق"
          → انتظار اعتماد الأدمن
        ❌ البيانات ناقصة
          → payment.status: "قيد المراجعة"
          → رسالة واضحة + زر تعديل البيانات
    ❌ الإيصال غير واضح/غير مطابق
      → payment.status: "قيد المراجعة"
      → رسالة واضحة + زر رفع إيصال جديد
```

### عند اعتماد الأدمن للعقار الجديد المدفوع

```
الأدمن يعتمد العقار
  → البحث عن آخر دفعة status: "نجح - قيد التحقق"
  → إنشاء الاشتراك من pendingStartDate / pendingEndDate
  → payment.status: "مكتمل"
  → verificationStatus: "approved"
  → إشعار المالك بتفعيل الاشتراك
```

## 4. التجديد Renewal / Extend

### القاعدة

- التجديد مسموح فقط عندما يتبقى 10 أيام أو أقل.
- التجديد يضيف الأيام بعد تاريخ نهاية الاشتراك الحالي.
- التجديد متاح عندما يكون الاشتراك نشطاً.

### تجديد بالدفع الإلكتروني

```
المالك يختار تمديد
  → إنشاء payment action: "extend"
  → pendingStartDate = تاريخ نهاية الاشتراك الحالي
  → pendingEndDate = pendingStartDate + مدة الباقة
  → الدفع ينجح
  → Smart Verify
    ✅ نجح → تفعيل تلقائي للعقار القديم
    ❌ فشل → الدفع يبقى "نجح - قيد التحقق" مع زر تعديل البيانات
```

### تجديد بالتحويل البنكي

```
المالك يرفع إيصال التحويل
  → AI يفحص الإيصال
    ✅ الإيصال مقبول
      → Smart Verify
        ✅ نجح → تفعيل تلقائي
        ❌ فشل → قيد المراجعة + زر تعديل البيانات
    ❌ الإيصال غير واضح/غير مطابق
      → قيد المراجعة + زر رفع إيصال جديد
```

## 5. الترقية Upgrade

### القاعدة

- الترقية مسموحة عندما يكون الاشتراك نشطاً.
- الترقية تبدأ من اليوم.
- الترقية تصفّر العداد ولا تضيف الأيام إلى تاريخ الانتهاء الحالي.
- قاعدة 10 أيام تخص التجديد فقط ولا تمنع الترقية.

### ترقية بالدفع الإلكتروني

```
المالك يختار ترقية
  → إنشاء payment action: "upgrade"
  → pendingStartDate = اليوم
  → pendingEndDate = اليوم + مدة الباقة الجديدة
  → الدفع ينجح
  → Smart Verify
    ✅ نجح → تفعيل الباقة الجديدة من اليوم
    ❌ فشل → payment.status: "نجح - قيد التحقق" + زر تعديل البيانات
```

### ترقية بالتحويل البنكي

```
المالك يرفع إيصال الترقية
  → AI يفحص الإيصال
    ✅ الإيصال مقبول
      → Smart Verify
        ✅ نجح → تفعيل الباقة الجديدة من اليوم
        ❌ فشل → قيد المراجعة + زر تعديل البيانات
    ❌ الإيصال غير واضح/غير مطابق
      → قيد المراجعة + زر رفع إيصال جديد
```

### نتائج الترقية

| الحالة | النتيجة |
|---|---|
| اشتراك نشط + Smart Verify ناجح | تبدأ الباقة الجديدة من اليوم |
| اشتراك نشط + Smart Verify فشل | لا تفعيل حتى استكمال البيانات |
| اشتراك غير نشط | رفض بدء الترقية، ويطلب اختيار اشتراك جديد |
| الباقة الجديدة تدعم عدداً أقل من المرتبطين | فصل العقارات الزائدة تلقائياً |

## 6. التحويل البنكي

### القاعدة

- التحويل البنكي يمر عبر Smart Verify مثل الدفع الإلكتروني.
- لا يتم تحويله للمراجعة اليدوية افتراضياً.
- المراجعة اليدوية تحدث فقط عند:
  1. فشل Smart Verify أو نقص البيانات.
  2. الإيصال غير صحيح أو غير واضح.
  3. تعذر التحقق من الإيصال لأي سبب تقني.

### التدفق

```
رفع إيصال التحويل
  → scanReceiptWithAI
    ✅ تفعيل_تلقائي
      → Smart Verify
        ✅ عقار قديم → تفعيل تلقائي
        ✅ عقار جديد → انتظار اعتماد الأدمن
        ❌ بيانات ناقصة → قيد المراجعة + زر تعديل البيانات
    ⚠️ مراجعة_يدوية / رفض / خطأ
      → قيد المراجعة
      → توضيح السبب
      → زر رفع إيصال جديد أو تعديل البيانات حسب السبب
```

## 7. الدفع الإلكتروني Card / Apple Pay

```
الدفع ينجح

  → Smart Verify
    ✅ عقار قديم → تفعيل تلقائي، payment.status: "مكتمل"
```

## 8. العقارات المرتبطة Linked Properties

### القاعدة العامة

- العقارات المرتبطة تأخذ نفس تواريخ اشتراك العقار الأساسي.
- عند تفعيل العقار الأساسي، العقارات المرتبطة المعتمدة ترث حالة التحقق.
- عند فشل التفعيل بعد بدء إنشاء الاشتراكات، يتم rollback لكل العقارات التي تم لمسها.
- إذا الباقة الجديدة لا تدعم نفس عدد العقارات المرتبطة، يتم فصل الزائد تلقائياً.

### الاشتراك الأول مع عقارات مرتبطة

```
المالك يختار باقة تدعم أكثر من عقار
  → يضيف أرقام العقارات المرتبطة
  → الدفع وSmart Verify
    ✅ العقار الأساسي قديم
      → تفعيل الأساسي والمرتبطين بنفس التواريخ
    ✅ العقار الأساسي جديد
      → حفظ الدفع والتواريخ
      → انتظار اعتماد الأدمن
      → عند اعتماد الأدمن: تفعيل الأساسي والمرتبطين بنفس التواريخ
```

### التجديد مع عقارات مرتبطة

```
تجديد العقار الأساسي
  → pendingStartDate = نهاية الاشتراك الحالي
  → pendingEndDate = نهاية الاشتراك + مدة الباقة
  → عند النجاح:
    - الأساسي يتجدد
    - كل المرتبطين يتجددون بنفس التواريخ
```

### الترقية مع عقارات مرتبطة

```
ترقية العقار الأساسي
  → البداية من اليوم
  → كل المرتبطين يأخذون نفس startDate/endDate
  → إذا الباقة لا تكفي للجميع:
    - يتم الاحتفاظ بالعدد المدعوم
    - يتم فصل الزائد تلقائياً
```

### التحويل البنكي مع عقارات مرتبطة

```
AI يقبل الإيصال
  → Smart Verify للعقار الأساسي
    ✅ قديم → تفعيل الأساسي والمرتبطين
    ✅ جديد → انتظار اعتماد الأدمن، ثم تفعيل الجميع عند الاعتماد
    ❌ فشل → قيد المراجعة ولا يتم إنشاء اشتراكات
```

### فشل Smart Verify

| الحالة | النتيجة |
|---|---|
| قبل إنشاء أي اشتراك | لا يتم تفعيل الأساسي أو المرتبطين |
| أثناء تفعيل المرتبطين | rollback لكل الاشتراكات التي تم إنشاؤها |
| إيصال غير واضح | قيد المراجعة، ولا يتم تفعيل أي عقار |

### تأثير حالة العقار الأساسي

| حالة الأساسي | تأثير المرتبطين |
|---|---|
| تم تفعيله | نفس تواريخ الاشتراك ونفس نوع الباقة |
| ينتظر اعتماد الأدمن | المرتبطون لا يتفعّلون بعد |
| ترقية/تجديد ناجح | تحديث الجميع معاً |
| فشل التفعيل | rollback للجميع |
| الباقة لا تكفي | فصل الزائد تلقائياً |

## 9. Smart Verify

### ما يفحصه

- اسم العقار.
- رقم واتساب المالك.
- الموقع.
- المدينة.
- الاتجاه.
- النوع.
- الأسعار.
- المرافق.
- وجود صور.

### النتائج

| النتيجة | عقار قديم | عقار جديد |
|---|---|---|
| مكتمل | يسمح بالتفعيل التلقائي | ينتظر اعتماد الأدمن |
| ناقص | لا تفعيل، زر تعديل البيانات | لا تفعيل، زر تعديل البيانات |

## 10. Run Verification

### العقار الجديد

- يعمل تلقائياً عند حفظ بيانات العقار الجديد.
- يعمل مرة واحدة بعد النجاح، ويتم حفظ علامة داخلية مثل `smartVerificationPassed`.
- بعد النجاح يبقى `verificationStatus: pending` حتى اعتماد الأدمن.
- إذا البيانات ناقصة يبقى العقار pending وتظهر الحقول المطلوبة.

### العقار القديم

- لا يتأثر بهذا التغيير.
- يستمر Auto Verify الحالي كما هو.
- إذا كان هناك دفع ناجح بانتظار التحقق، ونجح Run Verification، يتم التفعيل تلقائياً.

## 11. تجربة المستخدم عند الأخطاء

كل فشل أو نقص بيانات يجب أن يحتوي على:

1. سبب واضح بالعربية.
2. الخطوة التالية المطلوبة من المستخدم.
3. زر أو توجيه مباشر للصفحة المناسبة.

| الحالة | الرسالة المطلوبة | الزر |
|---|---|---|
| بيانات ناقصة | يرجى استكمال بيانات العقار: [الحقول] | تعديل بيانات العقار |
| إيصال غير واضح | يرجى رفع إيصال تحويل صحيح وواضح | رفع إيصال جديد |
| تعذر فحص الإيصال | تعذر التحقق من الإيصال تلقائياً | رفع إيصال جديد / متابعة الحالة |
| دفع ناجح لعقار جديد | تم التحقق، وبقي اعتماد الإدارة | متابعة الحالة |
| تمديد قبل الوقت | يمكن التمديد عند بقاء 10 أيام أو أقل | العودة للاشتراك |
| ترقية بدون اشتراك نشط | لا يمكن الترقية لأن الاشتراك غير نشط | اختيار باقة جديدة |

## 12. تنظيف المنطق القديم

### منطق ملغى

| القديم | الجديد |
|---|---|
| العقار الجديد المدفوع يتفعّل تلقائياً بعد Smart Verify | العقار الجديد المدفوع ينتظر اعتماد الأدمن |
| التحويل البنكي ينتظر الأدمن دائماً | يفحص AI ثم Smart Verify تلقائياً |
| فشل Smart Verify في التحويل البنكي يرفض الدفع فوراً | قيد المراجعة مع زر تعديل البيانات |
| الترقية تخضع لقاعدة 10 أيام | قاعدة 10 أيام للتمديد فقط |
| اعتماد العقار يغيّر حالة الدفع فقط | اعتماد العقار المدفوع ينشئ الاشتراك من بيانات الدفع المعلقة |

### منطق ثابت

| السلوك | الحالة |
|---|---|
| العقار القديم يتفعّل تلقائياً بعد الدفع وSmart Verify | مستمر |
| التجديد يضيف بعد تاريخ الانتهاء الحالي | مستمر |
| الترقية تبدأ من اليوم | مستمر |
| العقارات المرتبطة تأخذ نفس تواريخ الأساسي | مستمر |
| فصل الزائد عند عدم دعم الباقة للعدد | مستمر |
