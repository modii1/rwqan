## 2) التغييرات (جراحية، بأقل قدر ممكن)

1. `server/routes/admin/images.ts` — مسار رفع صور الأدمن كان يفتقد التحقق من محتوى الملف
   (كان يفرض `image/jpeg` ويعيد التسمية `.jpg` لأي رفع). أُضيف تحقق **magic-bytes** عبر
   `detectBookingCommissionReceiptContentType` (نفس ما يستخدمه مسار المالك)، فيُرفض المحتوى
   غير الصوري أو PDF بـ **415**، ويُخزَّن النوع المكتشف فعليًا (`jpg`/`png`/`webp`) بدل
   فرض `image/jpeg`. كما يُعاد `400` عند عدم وجود ملفات.
2. `server/index.ts` — معالج أخطاء API العام كان يعيد `500 {message:"Server Error"}` لأخطاء
   رفع الملفات (تُرمى من middleware الـ multer ولا تصل إلى `try/catch` الخاص بالمسار).
   أُضيف فرع يعيد **413** عند `LIMIT_FILE_SIZE` و`400` لبقية أخطاء Multer، مع رسالة واضحة.
   (هذا يصلح سلوك حدّ الحجم على مساري المالك والأدمن معًا.)
3. `scripts/dev/r2-dev-integration-test.ts` — **أداة اختبار تكامل DEV جديدة** (راجع القسم 6).

> لم تُعدَّل سياسات R2 ولا `next.config.ts` ولا أي مورد إنتاجي. الفجوة `R2-001` (خصوصية
> الإيصالات) بقيت كما هي عمدًا لأنها محجوبة بقرار موثّق (راجع القسم 5).

## 3) خريطة مسارات R2 العامة/الخاصة (كما هي بعد المرحلة)

- **صور العقارات (عامة بالتصميم — DEC-003):** قائمة عامة عبر
  `GET /api/public/property-images/:propertyNumber` (مقيّدة ببوابة `verificationStatus`

- **صور المالك (خاصة، قراءة موثّقة):** `GET /api/owner/r2-images` و

- **الإيصالات:** `POST /api/owner/payment/bank-transfer` و`/api/owner/addons/bank-transfer`
  (تحقق magic-bytes + حد الحجم، تخزين `receipts/...` و`addon-receipts/...`).
- **الأدمن:** `server/routes/admin/images.ts` (رفع/حذف/عدّ) — أُضيف تحقق المحتوى في هذه المرحلة.

## 4) حالات الاختبار (دليل التشغيل الفعلي على DEV)

| المعرّف | الحالة | النتيجة |
| --- | --- | --- |
| R2-UP-001 | رفع صورة عقار فعليًا إلى R2 (كتابة حقيقية) | PASS `200` |
| R2-URL-001 | رابط الخدمة وكيل أصلي على نفس النطاق (لا نطاق وهمي) | PASS |
| R2-RD-001 | قراءة المالك لصورته الخاصة ومطابقة المحتوى | PASS `200 image/png` |

| R2-UX-001 | ظهور الصورة في واجهة معرض المالك | PASS |
| R2-UX-002 | استمرار ظهور الصورة بعد إعادة تحميل الصفحة | PASS |
| R2-VAL-001 | رفض محتوى غير صورة (تحقق magic-bytes) | PASS `415` |
| R2-VAL-002 | رفض صورة تتجاوز حد 2MB | PASS `413` |
| R2-AUTH-001 | رفض قراءة صورة خاصة بدون جلسة | PASS `401` |

| R2-PRIV-001 | إيصال مخزَّن خاصًا وغير مُخدَّم/مُدرَج علنًا | PASS (وكيل عام `403`، موجود في الحاوية، غير مُدرج) |

**ملاحظة R2-SIGNED-001 (N/A):** النظام لا يُصدر أي روابط Presigned حاليًا؛ في DEV تُخدم
الصور الخاصة عبر وكلاء قراءة موثّقين (بلا روابط منتهية الصلاحية). بند «صلاحية الرابط
المؤقت» لا ينطبق حتى يُنفَّذ هدف DEC-003 (رابط GET موقّع 120 ثانية) — وهو **معلّق** بقرار.

## 5) الفجوات والمحجوب (لا تُتجاوز)

- **R2-001 (إيصالات بمفاتيح عامة قابلة للتخمين) — محجوب.** لم يُنفَّذ أي تصلّب لأن الحل
  يتطلب نموذج صلاحيات مستندات غير موجود: `DEC-004`/`DEC-012`
  (`ADMIN_DOCUMENT_SCOPE = BLOCKED_BY_MISSING_MODEL`). لا تُخترع أدوار ولا يُتجاوز
  `requireAdmin`. الأثر مُخفَّف جزئيًا في DEV: الحاوية خاصة ولا يوجد وكيل عام يخدم
  `receipts/...` (مؤكد بالاختبار R2-PRIV-001)، لكن أسماء المفاتيح ما زالت قابلة للتخمين
  في الإنتاج حتى قرار التصلّب.
- **`R2_PUBLIC_URL` وهمي في DEV** (`https://your-dev-public-r2-domain.example`, بلا DNS):
  لذلك كل قراءة خاصة/عامة في DEV تمرّ عبر وكلاء على نفس النطاق. أي `receiptUrl` مخزَّن
  (`receipts/...`/`addon-receipts/...`) غير قابل للفتح مباشرة في DEV (لا وكيل للإيصالات).
- **R2-002 (رجوع `R2_PUBLIC_URL` إلى نطاق إنتاجي) — مُخفَّف:** `assertR2DevIsolation` يلزم
  تحديد `R2_PUBLIC_URL` صراحةً في DEV ويرفض الافتراضي الإنتاجي عند الإقلاع. القيمة
  المدموجة `DEFAULT_R2_PUBLIC_URL` ما زالت موجودة في الكود (توثيق العمق: يتطلب قرارًا
  بتغيير سلوك الإنتاج). لا تغيير خارجي في هذه المرحلة.
- **R2-003 (غياب بوابة حالة العقار في قائمة الصور العامة) — مُخفَّف في شجرة العمل:**
  البوابة موجودة في `server/routes/public.ts` وتطابق بوابة `/api/properties/:id`
  (`property && property.verificationStatus && verificationStatus !== "approved"`).
  مؤكد بالاختبار R2-PUB-001 (403 لغير المعتمد، 200 للمعتمد). الماسح أبلغ عنها من خط
  أساس أقدم (القاعدة إرشادية).
- **FILES-004 (تمرير `propertyNumber` المُدخَل إلى مفاتيح التخزين) — مُخفَّف:**
  `parsePropertyNumberParam` يفرض `^[0-9]{4,8}$` ويرفض كل ما عدا ذلك، ويُستخدم في كل
  مسارات الأدمن الثلاثة. لا إمكانية لحقن مسارات. لا حاجة لتغيير كود.
