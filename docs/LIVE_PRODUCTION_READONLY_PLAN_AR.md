## 3. هوية Firestore منفصلة بصلاحيات قراءة فقط + خيارات المصادقة

### 3.1 خيارات المصادقة (فُحصت)

| الخيار | يعمل محليًا في DEV؟ | ملاحظة |
|---|---|---|
| **مفتاح JSON لحساب خدمة** (`credential.cert`) | **نعم** | الخيار الوحيد العملي من سيرفر التطوير المحلي (Windows). يُخزَّن في `.env.development.local` (غير متتبَّع). |
| **ADC / بيانات الاعتماد الافتراضية** (`credential.applicationDefault`) | **لا** | تتطلب خادم بيانات وصف GCP أو `GOOGLE_APPLICATION_CREDENTIALS`. غير متاحة محليًا (لا يوجد metadata server). |
| **Workload Identity Federation** | **لا (عمليًا)** | رموز قصيرة العمر بدون مفتاح طويل، لكنها تتطلب بنية GCP (مجامع هوية) — غير ملائمة لـ DEV محلي. |

- إنتاج (App Hosting/Cloud Run) يستخدم **ADC بدون مفتاح** عبر حساب الخدمة المرفق
  (`apphosting.yaml` لا يضبط `GOOGLE_APPLICATION_CREDENTIALS` ولا `serviceAccount`) — لكن هذا
  للسيرفر الإنتاجي، لا لسيرفر التطوير المحلي.
- **`firebase-admin` 13.6.1** يوفّر `admin.credential.{cert, refreshToken, applicationDefault}`
  (مؤكَّد)، لذا فإن التبديل بين مفتاح JSON وADC ممكن في الكود، لكن **محليًا يجب استخدام المفتاح**.

  `rwqan-sa-dev`)، `assertR2DevIsolation` (الحاوية يجب أن تكون `rwqan-sa-dev` ولا يُستخدم
  مضيف الإنتاج العام)، و`security/src/guards.ts` (يعتبر `projects/rwqan-757` إنتاجًا).
  هذه تمنع DEV من لمس الإنتاج حادثًا.
